# Feature Specification: ML Experiment Evolution Manager Initial MVP

**Feature Branch**: `chore/create-specification`

**Created**: 2026-09-01

**Status**: Draft

**Input**: User description: "機械学習モデルの改善を繰り返す開発者が、実験の目的、仮説、派生元、変更点、実行結果、および派生関係を後から確認できる初期MVPを定義する。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 実験を定義してRunを紐付ける (Priority: P1)

機械学習モデルを改善する開発者として、実験の目的と仮説を記録し、必要に応じて派生元のRunと変更条件を指定したい。外部で学習を実行した後、その結果のRunを実験に紐付け、何を検証した実験なのかを結果とともに参照できるようにするためである。

**Why this priority**: 目的・仮説・変更内容と実行結果を一つの実験として残すことが、比較や振り返りの基礎となるためである。

**Independent Test**: 目的と仮説を入力し、任意で派生元Runと変更条件を指定して登録する。外部で実行済みのRunを選択して紐付け、実験の詳細に入力内容とRunの情報が表示されれば価値を確認できる。

**Acceptance Scenarios**:

1. **Given** 開発者が新しい実験をまだ登録していない状態、**When** 実験の目的と仮説を入力して登録する、**Then** 新しい実験が作成され、目的と仮説を詳細で確認できる。
2. **Given** 開発者が利用可能なRunを確認できる状態、**When** 新しい実験の派生元としてRunを選択し、変更した条件を記録して登録する、**Then** 実験には派生元Runと変更条件が関連付けられる。
3. **Given** 目的と仮説を持つ実験が登録済みであり、外部で学習を実行済みのRunがある状態、**When** 開発者がそのRunを実験の実行結果として選択して紐付ける、**Then** 実験に関連するRun情報、実行条件、評価指標を後から確認できる。

---

### User Story 2 - 実験の全体像を確認する (Priority: P2)

機械学習モデルを改善する開発者として、登録済みの実験を一覧で確認し、関心のある実験の詳細を開きたい。過去の試行を探し、各実験の意図と結果を素早く振り返るためである。

**Why this priority**: 実験が蓄積された後に、個別の検証結果へ到達するための入口となるためである。

**Independent Test**: 複数の登録済み実験を一覧で確認し、任意の実験を選んで目的、仮説、関連するRun情報、実行条件、評価指標を確認できれば価値を確認できる。

**Acceptance Scenarios**:

1. **Given** 複数の実験が登録済みの状態、**When** 開発者が実験一覧を表示する、**Then** 各実験を識別して選択できる一覧が表示される。
2. **Given** 一覧に実験が表示されている状態、**When** 開発者が実験を一つ選択する、**Then** その実験の目的、仮説、関連するRun情報、実行条件、評価指標を確認できる。

---

### User Story 3 - 派生元との差分を振り返る (Priority: P3)

機械学習モデルを改善する開発者として、派生元Runと現在の実験について、何を変更し、評価結果がどう変化したかを確認したい。改善の仮説が結果に結び付いたかを判断するためである。

**Why this priority**: 実験の改善過程を理解する製品目的に直接つながるが、実験の作成と実行ができた後に価値を発揮するためである。

**Independent Test**: 派生元Runを持ち、評価結果が記録された実験を開く。派生元と現在の実験の条件差分および評価指標の差分を確認できれば価値を確認できる。

**Acceptance Scenarios**:

1. **Given** 派生元Runと現在の実験の実行条件が記録されている状態、**When** 開発者が条件差分を確認する、**Then** 派生元から追加、変更、削除された条件を区別して確認できる。
2. **Given** 派生元Runと現在の実験の評価指標が記録されている状態、**When** 開発者が結果差分を確認する、**Then** 共通する評価指標ごとに派生元の値、現在の値、増減を確認できる。
3. **Given** 派生元Runが指定されていない実験を開いている状態、**When** 開発者が差分を確認しようとする、**Then** 比較対象がないことを明確に確認できる。

---

### User Story 4 - 実験の派生関係を確認する (Priority: P4)

機械学習モデルを改善する開発者として、選択した実験に至るすべての祖先と、そこから派生したすべての子孫を確認したい。改善の流れを起点から末端まで追跡するためである。

**Why this priority**: 個々の比較だけでは見えない改善の経緯を把握できるが、派生関係を持つ実験データがあることを前提とするためである。

**Independent Test**: 複数世代の派生関係を持つ実験を選択し、祖先と子孫を順序付きの関係として確認できれば価値を確認できる。

**Acceptance Scenarios**:

1. **Given** 複数世代にわたる派生関係を持つ実験が登録済みの状態、**When** 開発者が任意の実験の派生関係を確認する、**Then** 起点から当該実験までのすべての祖先を派生順序とともに確認できる。
2. **Given** 複数世代にわたる派生関係を持つ実験が登録済みの状態、**When** 開発者が任意の実験の派生関係を確認する、**Then** 当該実験から派生したすべての子孫を派生順序とともに確認できる。
3. **Given** 派生元を持たない実験を開いている状態、**When** 開発者が派生関係を確認する、**Then** その実験が起点であることを確認できる。

### Edge Cases

- 目的または仮説が未入力のまま登録しようとした場合、登録を完了せず、入力が必要な項目を開発者に示す。
- 指定した派生元Runに実行条件または評価指標がない場合、利用可能な情報だけを表示し、比較できない項目を明示する。
- 現在の実験と派生元Runで共通する評価指標がない場合、結果差分を算出せず、比較できない理由を示す。
- 外部で実行済みのRunを紐付けようとしたが必要な情報を取得できない場合、紐付けを完了せず、利用者に再試行または別のRunの選択を促す。
- 実験の保存後に利用を終了して再開した場合、保存済みの実験、Run、条件、評価指標、および派生関係を確認できる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、登録済みの実験を一覧で表示し、利用者が各実験を識別して選択できるようにしなければならない。
- **FR-002**: システムは、利用者が実験の目的と仮説を必須情報として登録できるようにしなければならない。
- **FR-003**: システムは、利用者が新しい実験に対して派生元となる既存Runを任意で指定できるようにしなければならない。
- **FR-004**: システムは、利用者が派生元から追加、変更、または削除した実行条件を実験ごとに記録できるようにしなければならない。
- **FR-005**: システムは、利用者が登録済み実験の目的、仮説、派生元、変更条件、関連するRun情報、実行条件、および評価指標を詳細で確認できるようにしなければならない。
- **FR-006**: システムは、利用者が外部で実行済みのRunを選択し、登録済みの実験の実行結果として手動で紐付けられるようにしなければならない。
- **FR-007**: システムは、実験に手動で紐付けたRunについて、確認可能なRun情報、実行条件、および評価指標を記録し、後から確認できるようにしなければならない。
- **FR-008**: システムは、派生元Runが指定された実験について、派生元と現在の実験の実行条件の追加、変更、削除を比較表示できるようにしなければならない。
- **FR-009**: システムは、派生元Runが指定された実験について、共通する評価指標ごとに派生元の値、現在の値、および増減を比較表示できるようにしなければならない。
- **FR-010**: システムは、利用者が選択した実験について、起点から当該実験までのすべての祖先と、当該実験から派生したすべての子孫を、派生順序が分かる関係として確認できるようにしなければならない。
- **FR-011**: システムは、実験、関連するRun情報、実行条件、評価指標、変更条件、および派生関係を利用終了後も保持し、後から再確認できるようにしなければならない。
- **FR-012**: システムは、派生元がない、比較可能な情報が不足している、または学習実行が未完了である場合に、その状態と比較できない理由を利用者に明確に示さなければならない。

### Key Entities

- **実験**: 改善の目的と仮説を表す作業単位。任意の派生元Run、変更条件、および手動で紐付けられた一回以上のRunと関連付く。
- **Run**: 外部で実行された一回の学習の記録。実行状態、実行条件、評価指標を持ち、後続実験の派生元または実行結果となり得る。
- **実行条件**: 学習実行を特徴付ける、名前と値を持つ条件。派生元との差分として追加、変更、削除を識別できる。
- **評価指標**: 学習結果を評価する、名前と値を持つ測定値。派生元との比較では同じ名前の指標を対応付ける。
- **派生関係**: 新しい実験とその派生元Runを結ぶ関係。起点から選択した実験までの祖先、および選択した実験から末端までの子孫を、派生順序に沿ってたどるために用いる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者は、目的と仮説を入力して新しい実験を定義し、外部で実行済みのRunを実行結果として紐付けるまでを 3 分以内に完了できる。
- **SC-002**: 派生元Runを持つ実験では、利用者は詳細を開いてから 1 分以内に条件差分と共通評価指標の結果差分を確認できる。
- **SC-003**: 複数世代の派生関係を持つ実験では、利用者は選択した実験のすべての祖先とすべての子孫を、派生順序とともに 1 分以内に識別できる。
- **SC-004**: 代表的な実験定義、実行、比較、派生関係確認のシナリオにおいて、評価参加者の 90% 以上が補助なしで完了できる。
- **SC-005**: 保存済み実験を利用終了後に再確認する検証で、目的、仮説、実行結果、変更条件、派生関係の 100% が閲覧可能である。

## Assumptions

- 初期MVPの利用者は単一の開発チーム内の開発者であり、認証、権限管理、利用者間のアクセス制御は対象外とする。
- 実験の目的と仮説は、利用者が自由記述で入力する。
- 学習の実行はアプリケーション外で行う。一つの実験には複数の外部で実行済みのRunを手動で関連付けられ、派生元として選べるのは既存の一つのRunとする。
- 条件差分は、条件名と値を比較して追加、変更、削除として扱う。評価結果差分は、同名の評価指標だけを比較対象とする。
- 派生関係は、起点から選択した実験までのすべての祖先と、選択した実験から末端までのすべての子孫を、派生順序が分かる一覧として確認する範囲とし、グラフィカルな可視化は含めない。
- Decision、Reason、Next Actionの管理、全体状況を集約するDashboard、本番環境への自動配備、環境構築の自動化、高度な画面改善は初期MVPに含めない。
